# time_checker

Локальная карта времени в пути по Москве. Для режима «Метро + пешком» приложение
использует локальный [OpenTripPlanner](https://www.opentripplanner.org/): пешие
участки прокладываются по OpenStreetMap, а движение поездов и пересадки — по
GTFS-модели московского метро.

В setup закреплена версия OTP 2.4.0: это последняя Java 17-версия с API
travel-time surface, которое позволяет получить всю heatmap одним запросом.

## Запуск в PyCharm

Понадобятся Node.js 20+ и Java 17 (например, Eclipse Temurin 17). В терминале
проекта один раз выполните:

```bash
npm install
npm run otp:setup
npm run otp:build
```

`otp:setup` скачивает примерно 260 МБ: JAR OpenTripPlanner и свежий московский
OSM-экстракт. `otp:build` один раз строит локальный граф; на этой машине ему
выделяется до 8 ГБ RAM (`OTP_MEMORY=6G` позволяет изменить лимит). GPU не
используется — расчёт выполняется на CPU.

Затем создайте в PyCharm две npm-конфигурации и запустите их одновременно:

```bash
npm run otp:serve
npm run dev
```

Либо `npm run otp` сам скачает входные данные, при необходимости построит граф
и запустит OTP. Интерфейс будет доступен на <http://localhost:5173>, OTP — на
<http://localhost:8080>.

## Данные и точность

- Улицы, проходы, лестницы, тоннели и другие пешие ограничения: ежедневный
  городской PBF-экстракт BBBike/OpenStreetMap (ODbL).
- Станции, линии и соседство станций метро: Wikidata (CC0), файл
  `src/data/metro.json`.
- Расписание метро: воспроизводимая GTFS-модель, генерируемая командой
  `npm run generate:gtfs`. Она использует интервал 3 минуты, время стоянки и
  разгона между станциями и явные минимальные времена пересадок. Это не
  официальный прогноз движения поездов.

Платформы GTFS связываются со станциями OSM по идентификаторам Wikidata. Поэтому
OTP использует размеченные в OSM входы, лестницы и внутренние проходы, когда они
есть; для остальных станций действует ближайшая пешеходная связь и минимальное
время из `transfers.txt`.

OpenTripPlanner возвращает travel-time surface в GeoTIFF: для одной выбранной
точки выполняется один локальный запрос вместо сотен тысяч запросов по клеткам.
Для нескольких точек карта показывает максимальное время среди них — то есть
сколько нужно в худшем случае, чтобы место было достижимо от каждой точки.
