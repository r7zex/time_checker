# Время в пути

Локальное React-приложение показывает приблизительные зоны времени в пути до выбранной точки или от неё. Карта рассчитывается по редкой сетке реальных маршрутов Яндекс Карт, а промежутки визуально интерполируются в браузере. Так один расчёт использует 12, 24 или 40 маршрутных запросов вместо сотен.

## Возможности

- выбор точки кликом по карте;
- направления «к точке» и «от точки»;
- весь общественный транспорт, только метро, автобусы, трамваи или пешком;
- три уровня детализации;
- прозрачная тепловая карта с интервалами по 6 минут поверх обычной карты;
- локальный кеш расчётов на 6 часов;
- адаптивная панель для телефона.

> Яндекс строит общественный маршрут без входного фильтра по виду транспорта. Приложение проверяет типы сегментов каждой возвращённой альтернативы и оставляет только маршрут с выбранным видом транспорта. Пешие участки до остановки и после неё разрешены. Если подходящей альтернативы нет, точка не участвует в интерполяции.

## Какой API нужен

Только ключ **JavaScript API Яндекс Карт 2.1**. Геокодер не используется: точки передаются координатами, а `reverseGeocoding` отключён.

1. Скопируйте файл переменных:

   ```bash
   cp .env.example .env.local
   ```

2. Запишите ключ в `.env.local`:

   ```dotenv
   VITE_YANDEX_MAPS_API_KEY=ваш_ключ
   ```

3. В кабинете Яндекса ограничьте ключ адресами локальной разработки, например `http://localhost:5173`, и будущим доменом приложения.

Ключ JavaScript API технически загружается браузером, поэтому он не является серверным секретом, но ограничения по HTTP Referer обязательны. Не коммитьте `.env.local`.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`.

Для проверки интерфейса без маршрутных API-запросов:

```dotenv
VITE_DEMO_MODE=true
```

Демо всегда явно помечено и не выдаёт синтетические значения за реальные.

## Проверки

```bash
npm run lint
npm run test
npm run build
```

## Как экономятся запросы

- 12, 24 или 40 опорных точек: часть равномерно покрывает экран, часть идёт по
  многоуровневой спирали от выбранной точки до видимых пригородов;
- сама выбранная точка всегда добавляется как 0 минут без отдельного API-запроса;
- не более четырёх одновременных маршрутных расчётов;
- координаты выбранной и опорной точек округляются примерно до 100 м для повторного использования кеша;
- кеш хранится 6 часов и ограничен 500 записями;
- адреса не запрашиваются, поэтому Геокодер не расходуется;
- визуальная интерполяция выполняется локально на `canvas` без API.
