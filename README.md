# Время в пути

Локальное React-приложение строит зоны времени в пути по Москве от одной или
нескольких выбранных точек. По умолчанию выбраны координаты Центрального
телеграфа: `55.758272, 37.611014`.

Режим «Весь транспорт + пешком» использует локальный
[OpenTripPlanner](https://www.opentripplanner.org/): пешие участки прокладываются
по OpenStreetMap, а метро, автобусы, трамваи и пересадки входят в локальную
GTFS-модель. Маршрутных API и ключей не требуется.

## Как считается маршрут

OTP строит общий граф из двух источников:

1. улицы, дорожки, переходы, лестницы, тоннели и ограничения из OpenStreetMap;
2. станции, перегоны, частота поездов и минимальные времена пересадок из GTFS;
3. остановки и направления автобусов и трамваев из транспортных relations того
   же OSM-экстракта, преобразованных в GTFS при сборке графа.

Для каждой выбранной точки приложение запрашивает одну travel-time surface в
GeoTIFF с границей 120 минут и переносит её значения в сетку карты. Поэтому
детализация интерфейса не создаёт сотни тысяч маршрутных запросов. Для нескольких
точек итог клетки — максимальное время среди них: зона показывает места,
достижимые от каждой точки в заданный срок. В подписи клетки сохраняется время
для каждой точки отдельно. Значение OTP дополнительно сверяется с калиброванной
моделью метро непрерывной функцией без пороговых скачков, чтобы устранять
известные выбросы raster-маршрутизатора OTP 2.4 после пересадок, не отбрасывая
более быстрые наземные маршруты и OSM-барьеры.

Версия OTP закреплена на 2.4.0: она работает с Java 17 и предоставляет API
travel-time surface. Более новые версии OTP удалили этот аналитический API.

## Запуск в PyCharm

Понадобятся Node.js 20+ и Java 17 (например, Eclipse Temurin 17). Один раз
выполните в терминале проекта:

```bash
npm install
npm run otp:setup
npm run otp:build
```

`otp:setup` скачивает примерно 260 МБ: JAR OpenTripPlanner и свежий московский
OSM-экстракт. `otp:build` строит локальный граф. По умолчанию Java разрешено
использовать до 8 ГБ RAM; лимит можно изменить, например `OTP_MEMORY=6G`.
Видеокарта не используется — построение и поиск выполняются на CPU.

Затем создайте в PyCharm две npm-конфигурации и запустите их одновременно:

```bash
npm run otp:serve
npm run dev
```

Либо `npm run otp` сам подготовит отсутствующие данные, при необходимости один
раз построит граф и запустит OTP. Интерфейс будет доступен на
<http://localhost:5173>, OTP — на <http://localhost:8080>.

`otp:serve` проверяет дату графа. После обновления генератора, OSM, схемы метро
или конфигурации он автоматически один раз выполнит пересборку, поэтому старый
`graph.obj` не будет незаметно использовать прежние времена.

## Данные и точность

- карта и маршрутизация пешком: ежедневный городской PBF-экстракт
  [BBBike/OpenStreetMap](https://download.bbbike.org/osm/bbbike/Moscow/), ODbL;
- отображение карты: [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/),
  BSD-3-Clause;
- станции, координаты, линии и соседство станций: снимок
  [Wikidata](https://query.wikidata.org/) в `src/data/metro.json`, CC0;
- метро: GTFS, генерируемый командой `npm run generate:gtfs`, с временами
  перегонов и явными минимальными временами пересадок;
- автобусы и трамваи: актуальные направления и остановки из OSM; времена между
  остановками оцениваются по длине участка, типичной скорости и ожиданию.

GTFS-платформы связываются со станциями OSM по идентификаторам Wikidata. Поэтому
OTP использует размеченные в OSM входы, лестницы и внутренние проходы, когда они
есть; для остальных станций действует ближайшая связь с пешеходным графом.

Публичного официального полного GTFS-расписания Москвы в проекте нет. Точное
время ожидания конкретного транспорта, пробки и временные закрытия не
учитываются, поэтому результат не обязан совпадать с Яндекс Картами минута в
минуту. В отличие от прежней формулы по прямой, наземный транспорт, геометрия
пешей части и реальные барьеры теперь входят в маршрут. Режим «Только пешком»
пока остаётся быстрым приближённым расчётом.

## Возможности

- одна или несколько точек с отдельными цветами и разбивкой времени в клетке;
- отдельные режимы «Весь транспорт + пешком», «Только метро + пешком» и
  «Только пешком»;
- 55 296, 163 840 или 368 640 отображаемых клеток;
- heatmap с регулируемой непрозрачностью;
- включаемая зона «до N минут», ручной ввод и ползунок от 1 до 120 минут;
- непрозрачность выделения зоны от 0 до 100%;
- линии и станции действующего метро поверх карты;
- адаптивная панель для телефона.

### Актуальность схемы метро

Снимок Wikidata в `src/data/metro.json` содержит только уже открытые станции.
Участок Троицкой линии закреплён тестами в действующем порядке:
`ЗИЛ → Крымская → Академическая → Вавиловская → Новаторская`. ЗИЛ отображается
как обычная станция. Прямое соединение `ЗИЛ—Технопарк` запрещено отдельным тестом.

### Производительность карты

После расчёта цвета один раз записываются в растр размером с сетку. При
перемещении и масштабировании браузер переносит готовые строки растра, а числа
рисуются только для видимых и достаточно крупных клеток. Контур строится лишь по
границе между доступными и недоступными клетками.

## Обновление данных

Чтобы обновить снимок метро из Wikidata и затем пересобрать граф:

```bash
npm run update:metro
npm run otp:build
```

Чтобы обновить улицы, остановки и маршруты наземного транспорта, удалите
локальный `otp/data/Moscow.osm.pbf`, снова выполните `npm run otp:setup`, а затем
`npm run otp:build`. Каталоги `otp/data` и `otp/runtime` не коммитятся.

## Контрольные замеры Яндекс Маршрутов

Python-скрипт `scripts/measure_yandex_transit_controls.py` через официальный
JavaScript API 2.1 делает 24 двусторонних замера от Центрального телеграфа и
РУДН на Орджоникидзе к станциям в шести направлениях. Карта и браузер для этого
не нужны: входящий в проект Node.js запускает только официальный
`multiRouter.MultiRoute`. Успешные ответы сразу сохраняются в
`src/data/yandex-route-controls.json`, поэтому повторный запуск использует их
как кеш и не расходует запросы повторно. Локальный счётчик также запрещает
превысить 1 000 запросов за UTC-сутки.

Ключ читается только из переменной окружения и не записывается в проект:

```powershell
$env:YANDEX_MAPS_API_KEY="ключ из кабинета разработчика"
npm run measure:yandex-controls
```

Старое имя `YANDEX_ROUTER_API_KEY` тоже поддерживается. По умолчанию API получает
`Referer: http://localhost:5173/`; другое разрешённое значение можно передать
через `YANDEX_ROUTER_REFERER`.

Из каждой альтернативы сохраняются общее время, длина, время ходьбы и
пересадок, линии и типы транспорта. Значение считается строгим эталоном метро,
только если каждый транспортный сегмент имеет тип `underground`; ходьба до
станции, после станции и переходы между линиями разрешены. Автобусная или
смешанная альтернатива может быть сохранена для диагностики, но никогда не
попадает в `strictMetroMinutes`. Если в трёх прямых альтернативах чистого метро
нет, скрипт отдельно сравнивает пеший подход к заданным в плане ближайшим
станциям и продолжение строго на метро. Для текущего плана это максимум четыре
дополнительных запроса, поэтому стандартный лимит запуска равен 30 запросам.
